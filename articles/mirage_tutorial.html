THE VISION
What does Mirage do? OVERVIEW
Mirage generates complete video from audio. Given someone's voice, it creates a realistic video of a person delivering that speech — including lip sync, facial expressions, body gestures, and even the background scene. Unlike re-dubbing systems, Mirage generates from scratch.
Input → Output
"Films are 50 percent visual and 50 percent sound."

Mirage's key insight: use only self-attention to mix audio and video.
No specialized cross-attention. No domain-specific components.
Just concatenate all modalities and let attention figure it out.
🎬
A-Roll: the main footage

In filmmaking, "A-roll" is the primary footage — actors delivering lines, speakers addressing the camera. It's where audio and video must work in lockstep. Mirage is designed specifically for generating this type of content: realistic people speaking, gesturing, and performing in sync with audio.

CORE IDEA
Asymmetric Self-Attention THE KEY
The central design choice: all modalities share one attention mechanism. Text, audio, video, and reference image tokens are concatenated into a single sequence. Every token can attend to every other token. But each modality gets its own MLP and normalization — hence "asymmetric."
How tokens flow through a single transformer block
🍽️
Like a dinner party conversation

Imagine a dinner table where a filmmaker (video), a musician (audio), a writer (text), and a photographer (reference image) all sit together. They share one conversation (self-attention) — everyone hears everyone. But when they go home, each processes what they heard through their own expertise (modality-specific MLPs). No translator needed between them.

Why this matters — extensibility
The philosophical choice: Rather than designing specialized audio-video cross-attention modules (like EditYourself does), Mirage bets that with enough scale (10B params, 48 layers), standard self-attention can learn all the cross-modal correspondences implicitly. Adding a new modality is just concatenating more tokens.
ENCODERS
How each modality becomes tokens ENCODING
Each input modality goes through its own encoder to become a sequence of tokens. These token sequences are then concatenated along the sequence dimension before entering the transformer.
The four modality encoders
Final token sequence
Scale of the sequence: For a 4-second 720p video, the video tokens alone are 72,000 elements. Adding text (256), audio (~100), and optionally a reference image makes the full sequence enormous — requiring context parallelism across multiple GPUs.
POSITIONS
Learned 3D RoPE — per-modality positions SPATIAL
Each modality gets its own learned Rotary Position Embedding. Unlike fixed RoPE (as in EditYourself/LTX-Video), Mochi/Mirage learns the frequency schedule during training. Each modality has separate RoPE parameters — video gets 3D (time, height, width), audio gets 1D (time), text gets 1D (sequence position).
Per-modality position encoding
Interactive: How different modalities are positioned
Reference image positioning: The reference image is encoded through the same VAE as video (repeated 7 frames for minimum input size). Its RoPE time coordinate is set as the relative position of the reference frame to the video — so if the reference comes from 2 seconds before the generated clip, RoPE encodes that temporal offset.
TRAINING
Flow Matching — learning to generate DIFFUSION
Mirage uses flow matching (not DDPM). Instead of learning to predict noise, it learns to predict the velocity that flows from pure noise to the target video. This is mathematically cleaner and typically gives straighter sampling trajectories.
Flow matching intuition
🚀
Like navigating from random to meaningful

Imagine you're in a fog (Gaussian noise) and need to reach a destination (the target video). Flow matching learns the exact velocity vector at every point along the path. At inference, you follow these velocity vectors step by step from the fog to a clear destination. The path is a straight line in latent space — no meandering.

Modality dropout for classifier-free guidance
During training, each conditioning modality is randomly dropped out:
● Sometimes no text → model learns unconditional generation
● Sometimes no audio → model learns text-only generation
● Sometimes no reference image → model generates appearance from scratch

At inference, this enables classifier-free guidance (CFG): run the model with and without conditioning, amplify the difference. Plus STG and negative prompting for further quality.
CONDITIONING
Reference Image — controlling appearance IDENTITY
Mirage can optionally take a reference image to control the person's appearance. The image is encoded through the same VAE as video, then concatenated as extra tokens. No separate encoder, no face detection — just more tokens in the sequence.
How reference images enter the model
Mirage's approach
● Same VAE encoder as video
● Repeat image 7× temporally (VAE minimum)
● Same parameters as video tokens
● Only difference: RoPE time = relative offset
● No face detection needed
● No explicit masking
vs. EditYourself's approach
● Separate identity reference tokens
● Face detection → extract face patches
● Negative time coordinates
● Explicit conditioning mask per token
● Lower-face mask zeroing
● Precise spatial control
📸
Headshot vs. surgery

EditYourself is like a surgeon: it knows exactly where the mouth is, carefully masks it, and replaces just that region. Mirage is like giving an actor a headshot: "Look like this person" — and trusting the model to figure out the details. Both work, but for different tasks: EditYourself edits existing video precisely; Mirage generates entirely new video.

DATA
Training Data Pipeline CURATION
Mirage's quality depends heavily on its training data. The paper describes a comprehensive filtering pipeline to extract high-quality single-speaker A-roll clips from raw video data.
Data filtering funnel
Video captioning — structured descriptions
Each video gets a 4-part structured caption via VLMs (GPT-4o + Qwen):

● Appearance — physical description, hair, clothing, accessories
● Bearing — facial expression, gestures, engagement style
● Background — setting, objects, atmosphere
● Shot — camera angle, framing, lighting

A two-pass process: first extract static attributes from keyframes, then temporal dynamics from dense frame sampling. Finally an LLM synthesizes both into a single paragraph.
INFERENCE
Fast Generation — scaling to production SPEED
A 10B parameter model processing 72,000+ tokens needs serious optimization. Mirage uses distributed inference, quantization, and temporal caching to make generation practical.
Inference optimization stack
Time caching — the biggest win (40% speedup)
Key observation: In later denoising steps, attention outputs barely change between consecutive steps. And the conditional vs unconditional CFG outputs become very similar.

● FasterCache: Cache and reuse attention outputs from previous steps
● Skip redundant CFG computations when conditional ≈ unconditional
● No perceptual quality loss — the cached values are nearly identical anyway
● Result: 40% reduction in inference time
RESULTS
What Mirage Learns — emergent behaviors MAGIC
Without any explicit supervision for these behaviors, Mirage learns to generate remarkably detailed and synchronized audio-visual outputs. Here are the emergent capabilities the paper demonstrates.
Emergent capabilities
Audio-only generation — what the model infers
The most surprising finding: When given only audio (no text, no reference image), Mirage generates a visually appropriate person and environment. A deep male voice produces a different-looking person than a high female voice. Studio-quality audio produces indoor settings; noisy audio produces outdoor scenes. The model has learned latent correlations between acoustic properties and visual appearance.
